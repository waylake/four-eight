# 0004. 벡터 검색 대신 룰 인덱스를 쓴다

- 상태: accepted
- 날짜: 2026-07-27

## 맥락

[ADR 0002](./0002-separate-deterministic-engine-from-llm.md)에 따라 모델에게 근거 텍스트를 주어야 합니다. 근거를 고르는 방법이 문제입니다.

기본값처럼 여겨지는 방식은 RAG입니다. 명리 문헌을 청크로 나눠 임베딩하고, 명식 요약으로 유사도 검색을 합니다. 온디바이스에서도 가능합니다.

그런데 사주의 온톨로지는 완전히 닫혀 있습니다. 천간 10, 지지 12, 십신 10, 오행 5, 십이운성 12입니다. 조합은 유한하고 열거 가능합니다. 이런 영역에서 임베딩 유사도는 정확도를 떨어뜨리기만 합니다. "편재"를 찾아야 하는데 "정재" 청크가 딸려 오는 식입니다.

## 결정

`FactExtractor`가 명식에서 태그 배열을 뽑고, `RuleSet`이 태그로 규칙을 정확 조회합니다.

```
ilgan:병  strength:신강  oheng_excess:목  oheng_lack:금  sibsin:편인  daeun_sibsin:편관
```

규칙은 `SajuKit/Sources/SajuKit/Resources/rules.json`에 있으며, 각 규칙은 자기가 매칭될 태그를 선언합니다. 조회는 해시 인덱스입니다.

## 결과

- 잘못된 근거가 딸려 올 수 없습니다. 태그가 맞거나 안 맞거나 둘 중 하나입니다.
- 임베딩 모델도, 벡터 저장소도 필요 없습니다. 앱이 그만큼 가벼워집니다.
- **어떤 문장이 어떤 규칙에서 나왔는지 항상 압니다.** UI의 근거 칩이 여기서 나옵니다. 이것이 이 앱의 가장 큰 차별점이 되었습니다.
- 대신 규칙을 사람이 써야 하고, 태그 규약을 지켜야 합니다. 현재 60개이며 확장 계획은 [research/interpretation-content.md](../research/interpretation-content.md)에 있습니다.
- 문헌 전체를 다루는 자유 질의응답은 이 구조로 안 됩니다. 대화 기능을 붙일 때 재검토가 필요합니다.

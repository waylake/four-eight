# 0001. 아키텍처 결정을 기록한다

- 상태: accepted
- 날짜: 2026-07-27

## 맥락

이 프로젝트에는 되돌리기 어려운 선택이 여럿 있습니다. 계산과 생성의 경계를 어디에 둘 것인가, 천문 라이브러리를 쓸 것인가, 유파가 갈리는 지점을 어떻게 다룰 것인가 같은 것들입니다. 이런 결정은 코드만 봐서는 이유를 알 수 없고, 커밋 메시지로 남기기에는 맥락이 깁니다.

특히 사주 도메인은 "왜 이 방식이냐"는 질문이 반복해서 들어올 영역입니다. 기여자와 사용자 모두에게 근거를 제시할 수 있어야 합니다.

## 결정

[MADR](https://adr.github.io/madr/) 형식으로 `docs/adr/`에 기록합니다. 형식 자체는 가볍게 유지합니다. 맥락, 결정, 결과 세 절이면 충분합니다.

조사 노트는 `docs/research/`에 별도로 두고, 조사 결론이 결정으로 굳으면 ADR로 승격합니다.

## 결과

결정 하나마다 파일 하나가 늘어납니다. 그 대신 "왜"에 답하는 비용이 사라집니다. 뒤집힌 결정도 `superseded`로 남겨 왜 뒤집었는지까지 추적할 수 있습니다.

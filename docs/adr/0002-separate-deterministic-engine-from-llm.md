# 0002. 계산 엔진과 언어 모델을 분리한다

- 상태: accepted
- 날짜: 2026-07-27

## 맥락

사주 앱에 언어 모델을 붙이는 방법은 크게 둘입니다.

하나는 생년월일시를 그대로 모델에 주고 명식까지 맡기는 것입니다. 구현이 단순하고 프롬프트 한 장이면 끝납니다. 문제는 모델이 산술을 못 한다는 것입니다. 육십갑자 순환, 절기 경계 비교, 율리우스일 계산은 유효 파라미터 2B 모델이 안정적으로 해낼 수 있는 작업이 아닙니다. 그럴듯하게 틀린 명식이 나오고, 사주 앱에서 명식이 틀리면 나머지는 의미가 없습니다.

다른 하나는 계산을 코드로 확정하고 모델에게는 문장화만 시키는 것입니다.

## 결정

모든 계산은 `SajuKit`이 수행합니다. 네 기둥, 십신, 십이운성, 신살, 공망, 합충, 오행 분포, 신강신약, 대운이 전부 포함됩니다.

모델은 `Interpreter` 프로토콜의 한 구현일 뿐이며, 확정된 사실과 선별된 규칙 원문을 받아 문장으로 엮습니다. 시스템 지시에 "제공된 내용만 사용하고 새로운 간지나 십신을 만들지 말 것"을 명시합니다.

모델이 없어도 앱은 완전히 동작해야 합니다. `TemplateInterpreter`가 규칙 원문을 그대로 조립합니다.

## 결과

- 명식이 틀릴 수 없습니다. 계산은 테스트로 고정되어 있습니다.
- 작은 모델로 충분합니다. E2B 4-bit 3.6 GB면 됩니다.
- 모델 다운로드가 선택 사항이 됩니다. 첫 실행에서 3.6 GB를 요구하지 않아도 됩니다.
- 해석의 출처를 추적할 수 있습니다. 이것이 [ADR 0004](./0004-rule-index-over-vector-retrieval.md)의 전제가 됩니다.
- 대신 규칙 콘텐츠를 사람이 써야 합니다. 모델에게 지식을 맡기지 않기로 했으므로 지식은 저장소 안에 있어야 합니다.

# 해석 콘텐츠 룰셋

`SajuKit/Sources/SajuKit/Resources/rules.json`에 수록된 해석 룰 60개의 집필 원칙, 스키마, 태그 규약, 확장 계획.

조사일: 2026-07-27

## 이론 기준

자평명리(子平命理) 정통 이론을 기준으로 하고, 조후(調候)는 궁통보감(窮通寶鑑)의 조후 관점을 개요 수준으로 반영했다.

| 영역 | 기준 |
|---|---|
| 일간 | 십천간의 물상 — 갑=거목, 을=화초·덩굴, 병=태양, 정=등촉, 무=산, 기=전답, 경=원석·무쇠, 신=보석·서리, 임=강해(江海), 계=우로(雨露) |
| 십신 | 생극 관계 — 비겁=동기, 식상=내가 생함, 재성=내가 극함, 관성=나를 극함, 인성=나를 생함. 편관은 칠살(七殺) 병기 |
| 조후 | 인묘진(봄)·사오미(여름)·신유술(가을)·해자축(겨울). 사고지(진=수고, 미=목고, 술=화고, 축=금고)와 장생지(신월=수 장생, 해월=목 장생)를 언급. 한랭한 월은 화(丙·丁), 조열한 월은 수(壬)를 조후 관건으로 제시 |
| 신살 | 미신적 길흉 단정 대신 현대적 재능·성향 해석 — 귀인=인복·네트워크, 도화=대중적 매력, 역마=이동 적응력, 화개=고독 속 몰입, 공망=집착 내려놓기 |
| 신강·신약·중화 | 억부(抑扶) 관점. 신강=식상·재관으로 설기, 신약=인성·비겁으로 부조, 중화=자평이 귀히 여기는 균형 |

## 집필 원칙

모든 신규 항목에 동일하게 적용하는 톤 체크리스트다.

- 존댓말을 쓰고, 2~4문장, 상담가 톤으로 쓴다.
- 단정하지 않는다. "~한 편입니다 / ~경향이 있습니다 / ~수 있습니다" 어미를 쓴다.
- 운명론적 공포나 미신 표현을 쓰지 않는다.
- 의료·투자·법률 조언을 하지 않는다. 생활 습관과 일정 관리 수준의 조언까지만 허용한다.
- 실용 조언을 1문장 포함한다. 해당 간지나 십신 고유의 구체적 행동이어야 한다.
- 이모지를 쓰지 않는다. 한자는 첫 등장 시 괄호로 병기한다.
- 뻔한 일반론을 쓰지 않는다. 각 항목은 해당 개념의 물상·생극 논리에서 도출한다.

이 원칙은 앱 성격상 타협 대상이 아니다. 사주 해석은 읽는 사람의 불안을 자극하기 쉬운 장르이고,
룰 텍스트가 곧 모델에게 주어지는 재료이므로 원본 텍스트에서 톤을 통제하지 않으면 생성물에서 통제할 방법이 없다.

## 룰 스키마와 태그 규약

파일: `SajuKit/Sources/SajuKit/Resources/rules.json` (`version: 1`, `rules` 배열 60개).

각 룰의 필드는 다음과 같다.

| 필드 | 설명 |
|---|---|
| `id` | 대문자 스네이크 케이스 식별자 (예: `ILGAN_GAP`, `OHENG_EXCESS_MOK`) |
| `category` | 아래 8개 중 하나 |
| `title` | 한글 표제 (예: "갑목 일간") |
| `hanja` | 한자 표기 (예: `甲木`) |
| `tags` | 매칭 키. 현재 전 항목이 1개 |
| `text` | 해석 본문. 집필 원칙 적용 대상 |

### 카테고리 구성

| category | 개수 | tag prefix | 예시 tag |
|---|---|---|---|
| `ilgan` | 10 | `ilgan:` | `ilgan:갑` |
| `sibsin` | 10 | `sibsin:` | `sibsin:비견` |
| `oheng_excess` | 5 | `oheng_excess:` | `oheng_excess:목` |
| `oheng_lack` | 5 | `oheng_lack:` | `oheng_lack:목` |
| `strength` | 3 | `strength:` | `strength:신강` |
| `johu` | 12 | `wolji:` | `wolji:인` |
| `sinsal` | 5 | `sinsal:` | `sinsal:천을귀인` |
| `daeun_sibsin` | 10 | `daeun_sibsin:` | `daeun_sibsin:비견` |
| 합계 | **60** | | |

기획 스펙에는 "TOTAL 55"로 적혀 있었으나 세부 명세를 합산하면 60이다(10+10+10+3+12+5+10 = 60,
오행은 과다 5 + 부족 5). 합산 오차로 판단하고 세부 명세를 우선해 60개를 전부 수록했다.

### 태그 접두사 정규화

집필 노트 단계의 초안은 오행 항목에 공통 접두사 `oheng:`을 쓰고 과다·부족은 `category`로만 구분하려 했다
(예: `oheng_lack` + `oheng:목` 조합 조회). 실제 반영본은 접두사 자체를 `oheng_excess:` / `oheng_lack:`으로 나눴다.

그 결과 모든 카테고리에서 태그 하나가 조회 키로 충분해졌고, category와 tag를 조합해야만 정확히 찾을 수 있는 예외가 사라졌다.
`oheng:목`이라는 태그는 현재 파일에 존재하지 않으므로, 초안 표기를 참조하는 코드가 있다면 정정해야 한다.

예외는 `johu` 카테고리다. 조후 룰의 태그는 `johu:`가 아니라 `wolji:`(월지)를 쓴다.
현행 12개가 일간과 무관한 월지 기준 개요이기 때문이며, 아래 확장 계획의 일간×월지 120룰과 접속하기 위한 형태이기도 하다.

## 태그 매칭이 벡터 검색이 아닌 이유

사주는 닫힌 온톨로지다. 천간 10개, 지지 12개, 십신 10개, 오행 5개로 개념 집합이 고정되어 있고 새 항목이 생기지 않는다.
엔진이 산출하는 것도 자유 텍스트가 아니라 이 집합의 원소들이다. 즉 조회 대상과 조회 키가 같은 유한 집합에서 나온다.

이런 조건에서 임베딩 유사도 검색은 이득 없이 손해만 준다.

- 정확한 키가 이미 있는데 근사 검색을 하면 틀릴 여지만 생긴다. `sibsin:정관`을 찾는데 편관 룰이 딸려 올 이유가 없다.
- 결정성이 깨진다. 같은 입력에 같은 해석이 나와야 회귀 테스트가 가능하다.
- 근거 표시가 흐려진다. 앱은 문장마다 어떤 룰에서 나왔는지 칩으로 보여주는데, 유사도 상위 k개를 넣는 방식은 이 대응을 흐린다.
- 임베딩 모델과 벡터 인덱스라는 런타임 의존성이 생긴다. `SajuKit`은 런타임 의존성이 없는 것이 설계 목표다.

따라서 검색은 결정적 태그 조회다. 엔진이 사실 태그 집합을 만들고, 그 태그로 룰을 인덱싱해 꺼낸다.
모델에게는 고정된 사실 집합과 고정된 룰 텍스트가 주어지고 그것만 조합하라는 지시가 붙는다.
2B 파라미터 모델로 충분한 이유이자, 해석문이 존재하지 않는 기둥을 지어낼 수 없는 이유다.

이 판단은 [ADR-0004 벡터 검색 대신 룰 인덱스를 쓴다](../adr/0004-rule-index-over-vector-retrieval.md)로 승격되었다.

## 확장 계획

`version` 필드는 스키마 변경 시 올린다. 아래 항목은 모두 동일 스키마에 `category`를 추가하는 방식으로 확장 가능하다.

| 우선순위 | 항목 | 내용 |
|---|---|---|
| 1 | 일간×월지 조후 120룰 | `JOHU_<일간>_<월지>`, tags `ilgan:갑` + `wolji:인`. 궁통보감 조후용신 기준으로 현행 12개 개요를 세분화 |
| 2 | 세운 (`SEUN_SIBSIN_*`) | 대운 문구를 1년 단위 호흡으로 변형. 단기 실행 조언 톤 |
| 3 | 십신 위치별 (연·월·일·시) | 동일 스키마에 category 추가 |
| 3 | 지장간, 12운성, 합충형파해 | 동일 스키마에 category 추가 |
| 4 | 신살 확장 (월덕·천덕, 양인, 백호 등) | 현대적 해석 원칙 유지. 공포 조장 표현 금지 |

톤 일관성은 사람 검수에 맡기지 말고 CI 스크립트로 검사하는 것을 권장한다. 검사 항목은
문장 수(2~4), 금칙어("반드시 ~된다", "조심하지 않으면 ~한다" 류의 단정·공포 표현), 이모지 유무다.
1번 항목의 120룰처럼 수량이 커지면 수작업 검수는 현실적으로 유지되지 않는다.

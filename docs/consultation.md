# 상담 기능 기획

- 작성: 2026-07-28
- 결정 근거: [ADR 0010](./adr/0010-consultation-over-open-chat.md)
- 사실 근거: [consultation-safety.md](./research/consultation-safety.md) (규제·안전·모델 한계) · [consultation-references.md](./research/consultation-references.md) (제품 레퍼런스)

이 문서는 무엇을 만들었고 왜 그렇게 만들었는지를 화면 단위로 적습니다. 코드에 없는 판단이 여기 있습니다.

## 1. 예전 대화 기능과 무엇이 다른가

| | 예전 (0.1.x) | 지금 |
|---|---|---|
| 단위 | 인물당 대화 세션 하나 | **고민 하나에 대한 상담 한 건** |
| 상태 | 뷰의 `@State` — 인물 바꾸면 소실 | 디스크에 보관, 며칠에 걸쳐 이어감 |
| 컨텍스트 | 명식의 **모든** 근거를 시스템 지시에 | 축을 정하고 **그 축의 근거만** |
| 근거 표시 | 없음 | 상담 헤더와 답변에 근거 칩, 클릭하면 원문 |
| 시작 | 빈 입력창 + 추천 질문 | 고민을 받고 앱이 축을 정하고 **되묻는다** |
| 모델 필요 시점 | 화면에 들어가려면 필요 | **풀이를 주문할 때만** |
| 멀티턴 | 세션 하나에 이력 누적 | 매 턴 새 세션 + 근거 재주입 |
| 시간 축 | 없음 | 오늘·이번 달·올해·대운을 선택적으로 |
| 안전 | 지시문 한 줄 | 모델 호출 **전에** 결정론적 선별 |
| 한계 고지 | 없음 | 무엇을 보고 무엇을 기억하지 않는지 화면에 |
| 내보내기 | 없음 | 마크다운, 근거 ID 포함 |

핵심은 마지막 줄이 아니라 세 번째 줄입니다. **답이 근거에 매여 있고, 그 매임이 화면에 보입니다.**

## 2. 화면 기획

### 2.1 구조

```
사이드바 ┃ 지난 상담(있을 때만)  ┃ 상담 상세 또는 새 상담
        ┃ · 새 상담              ┃
        ┃ · 2026-07-28 이직…    ┃
        ┃   [일과 진로] 풀이 전  ┃
```

지난 상담이 없으면 목록 칸을 **띄우지 않습니다.** 첫 스크린샷에서 빈 목록이 한 열을 차지해 정작 고민을 적을 자리가 좁아졌습니다.

### 2.2 새 상담 — 고민을 받는 화면

```
무엇이 마음에 걸리십니까
있는 그대로 적어 주세요. 앱이 어떤 명리 축의 이야기인지 먼저 정하고,
그 축의 근거만 가지고 풀이합니다.

┌───────────────────────────────────────────┐
│ 예: 지금 회사를 계속 다녀야 할지 몇 달째    │
│ 마음이 왔다 갔다 합니다.                   │
└───────────────────────────────────────────┘
                                  [ 상담 열기 ]

이 명식에서 이야기할 수 있는 축
[나와 성향 일간·신강약] [일과 진로 관성·식상·신강약] [관계와 인연 …]
이 명식에는 돈과 재물, 사람과 조직 쪽 근거가 성립하지 않아 권하지 않습니다.

✓ 이 상담은 계산된 명식과 근거 규칙만 봅니다
  근거에 없는 것은 지어내지 않고 모른다고 답합니다. …
▣ 풀이는 이 Mac에서 돌아가는 AI 모델이 씁니다. 사람이 아니고,
  심리 상담이나 치료가 아니며, 면허 있는 전문가의 도움을 대체하지 않습니다.
```

여기서 **모델은 한 번도 호출되지 않습니다.** 축 칩은 이 명식에서 근거가 성립하는 것만 보이고, 성립하지 않는 축은 왜 권하지 않는지 적습니다.

축을 명시하는 이유가 하나 더 있습니다. 사용자가 무엇을 물을 수 있는지 배웁니다. 추천 질문 목록보다 정확하고, 답할 수 없는 것을 권하지 않습니다.

### 2.3 상담 상세

```
┌ [일과 진로 ▾] 관성 · 식상 · 신강약        [오늘 기운 함께 ●] ┐
│ '이직', '회사'를 보고 이 축으로 읽었습니다.                   │
│ [정관] [상관] [신강한 사주]        ← 쓰이는 근거, 답 전에 보임 │
└───────────────────────────────────────────────────────────┘

적어 주신 고민
지금 회사를 계속 다녀야 할지 …

▣ 앱  지금 자리에서 가장 걸리는 것이 일의 내용인지, 함께 일하는
      사람인지, 아니면 앞으로의 방향인지 알려 주시면 근거를 좁혀 보겠습니다.

                                    상담자가 덧붙인 말 ▶

명리 풀이  (AI 모델)
  …
  Gemma 4 · 7월 28일 오후 3:12

이 상담은 근거 3개와 최근 발언 4개를 봅니다.
그 밖의 것은 기억하지 않습니다. …
▣ 풀이는 이 Mac에서 돌아가는 AI 모델이 씁니다. …

┌─────────────────────────────────────────┬──────────────────┐
│ 되물음에 답하거나 사정을 덧붙여 주세요    │ [적어만 두기] [풀이 받기] │
└─────────────────────────────────────────┴──────────────────┘
```

세 화자를 시각적으로 구분합니다.

| 화자 | 표시 | 의미 |
|---|---|---|
| 상담자 | 오른쪽 말풍선 | 사용자가 적은 것 |
| **앱** | 가운데 회색 카드, 책 아이콘 | **결정론적으로 확정된 말** — 되묻기, 한계 고지, 안전 안내 |
| 명리 풀이 (AI 모델) | 왼쪽 종이 카드 + 모델·시각 | 생성된 것 |

기계가 확정한 말과 모델이 쓴 말을 같은 모양으로 두면, 사용자는 어느 쪽이 흔들릴 수 있는 말인지 알 수 없습니다.

### 2.4 위기 화면

```
♡ 지금은 명식보다 사람이 필요한 이야기입니다

적어 주신 글에서 많이 힘든 상태가 느껴집니다. 이런 이야기에 사주
풀이로 답하는 것은 도움이 되지 않는다고 생각합니다. …

  자살예방 상담전화  109        전화·문자, 24시간
  자살예방 상담전화  1393       24시간
  정신건강 위기상담  1577-0199  24시간

어느 번호로 걸어도 됩니다. 통합 번호(109)와 기존 번호가 함께 안내되고 있습니다.
이 글은 저장하지 않았습니다. 이 Mac 밖으로도 나가지 않았습니다.
```

**모델을 부르지 않고, 상담 기록도 만들지 않습니다.** 번호를 하나로 정리하지 않은 이유는 조사에서 자료가 어긋났기 때문입니다(§2.2 of 조사 노트).

## 3. 기능 기획

### 3.1 흐름

```
고민 입력
   │
   ├─ 안전 선별 (결정론적, 모델 없음)
   │    ├─ 위기      → 고정 안내 + 상담 전화. 기록 없음. 끝.
   │    └─ 범위 밖   → 한계를 먼저 밝히고 계속
   │
   ├─ 축 라우팅 (키워드 정확 매칭)
   │    ├─ 성공      → 그 축으로
   │    └─ 실패      → 사용자가 직접 고름 (짐작하지 않음)
   │
   ├─ 근거 선별 (이 명식의 사실 ∩ 축의 태그 필터)
   │
   ├─ 되묻기 (축마다 고정 문구)
   │
   ▼  여기까지 0초, 모델 불필요
사용자가 [풀이 받기]를 누름
   │
   ├─ 모델 적재 (필요할 때만, "불러오는 중" 표시)
   ├─ 프롬프트 조립 = 사실 + (오늘) + 축 + 근거 + 고민 + 최근 4발언
   └─ 스트리밍 → 근거 칩과 함께 기록 → 디스크
```

### 3.2 축 라우팅

`ConsultationTopic` 10개. 각 축은 표시명, **명리 축(화면에 보임)**, 태그 필터, 되묻기 문구, 키워드를 갖습니다.

| 축 | 명리 축 |
|---|---|
| 나와 성향 | 일간 · 신강약 |
| 일과 진로 | 관성 · 식상 · 신강약 |
| 돈과 재물 | 재성 |
| 관계와 인연 | 재성 · 관성 · 도화 |
| 배움과 자격 | 인성 |
| 사람과 조직 | 비견 · 겁재 · 천을귀인 |
| 표현과 창작 | 식신 · 상관 |
| 몸과 마음의 기운 | 오행 균형 · 조후 |
| 이동과 거처 | 역마 · 지지 충 |
| 지금 이 시기 | 대운 · 세운 · 월운 · 일진 |

형태소 분석을 하지 않습니다. 한국어에서 "이직할까요"는 "이직"을 부분 문자열로 포함하므로 어미 처리 없이 잡힙니다. 못 잡는 문장은 인정하고 사용자에게 넘깁니다.

**임베딩을 쓰지 않는 이유**는 ADR 0004와 같습니다. 십신 10개가 사람이 겪는 일의 범주를 이미 나눠 놓았으므로 조합이 유한하고 열거 가능합니다.

### 3.3 근거 선별

```
이 사람의 사실 태그  ∩  축의 태그 필터  →  ruleSet.matching(tags:)
```

주제에 해당하는 규칙을 전부 넣지 않습니다. **재성이 없는 명식에 재성 설명을 붙이면 그것은 이 사람의 이야기가 아닙니다.** 테스트가 두 방향으로 검사합니다 — 근거가 이 명식의 사실에서 나왔는지, 그리고 축 밖 근거가 섞이지 않았는지.

### 3.4 풀이 — 매 턴 새 세션

프롬프트 구성:

```
[명식 사실]        이미 확정된 값
[오늘의 기운]      토글이 켜졌을 때만
[상담 주제]        일과 진로 — 관성·식상·신강약로 읽습니다
[근거]             3~6개, 규칙 원문
[처음 적은 고민]
[최근 주고받은 말] 최근 4개
[지금 덧붙인 말]
```

시스템 지시에 명시한 것: 근거 밖 금지, 모르면 모른다고, **결정을 대신하지 않음**, 등급 금지, 단정 금지, **아첨 금지**, 의료·투자·법률 금지, 공포 조장 금지. 쓰는 방식으로 첫 문장에 사정을 되짚고, 2~3문단, 마지막에 지시가 아니라 관점 하나.

측정된 근거는 조사 노트에 있습니다. 요약하면 세 가지입니다.

- 다중 턴은 39% 떨어지지만 **단일 턴으로 재구성(Concat)하면 95.1%**입니다.
- MLX의 열린 PR #414 — **중단 후 이어가면 KV 캐시에 종결자 없는 잘린 턴이 남아 전사가 깨지고, Gemma 계열이 특히 영향받습니다.** 이 앱에는 중단·재개가 있습니다.
- `ChatSession`은 어차피 매 턴 시스템 지시를 다시 렌더합니다(#367 미병합). 이력 재사용의 이득이 알려진 것보다 작습니다.

### 3.5 사용자가 할 수 있는 것

| 행위 | 모델 호출 | 비고 |
|---|---|---|
| 상담 열기 | 없음 | 축·근거·되묻기까지 |
| 적어만 두기 | 없음 | 사정만 기록. 나중에 이어감 |
| 풀이 받기 / 이어 묻기 | 있음 | 버튼을 눌러야만 |
| 중단 | — | 쓰던 문장은 남음 |
| 축 바꾸기 | 없음 | 근거가 함께 바뀜 |
| 오늘 기운 함께 보기 | 없음 | 다음 풀이에 반영 |
| 상담 삭제 / 내보내기 | 없음 | 마크다운에 근거 ID 포함 |

### 3.6 한계를 화면에 적는다

- "이 상담은 근거 N개와 최근 발언 4개를 봅니다. 그 밖의 것은 기억하지 않습니다."
- 풀이가 4회를 넘으면: "이 상담이 길어졌습니다. 새 고민은 새 상담으로 여시면 근거가 더 정확합니다."
- 모델이 답을 내지 못하면(Gemma 3 4B의 응답률은 67.3%입니다): "모델이 이 근거로는 답을 내지 못했습니다. 위의 근거 원문이 이 주제에 대해 확정된 내용입니다."
- 명식 서명이 달라진 상담: "유파 설정이 달라진 뒤의 명식입니다."

## 3.7 레퍼런스와 어긋나게 만든 지점

조사한 점성술·사주 앱 12개 중 **AI 답변에 근거를 붙이는 것을 확인한 것은 Co-Star의 The Void 하나**였고, 그것도 유료 질문에만 있습니다. **The Pattern은 점성술 용어와 근거를 의도적으로 제거**하는 것을 전략으로 밝히고, **CHANI는 AI 생성 콘텐츠가 없다는 것**을 약속으로 내세웁니다.

즉 이 시장의 두 갈래는 "근거 없이 매끄럽게" 또는 "AI 없이 사람이"입니다. 이 앱은 세 번째를 택했습니다 — **근거를 먼저 고정하고 AI에게 문장만 맡기는 것.**

근거를 붙이는 방식에서도 측정 자료를 따랐습니다.

- Pew: AI 요약이 있을 때 **인용 링크 클릭은 전체 방문의 1%** 수준입니다. → 근거 칩을 답 뒤에만 두면 읽히지 않습니다. **풀이를 받기 전에** 헤더에서 보여줍니다.
- Tow Center: AI 검색엔진의 **인용 오류율이 60% 이상**입니다. → 오류는 **모델이 인용을 생성하기 때문에** 생깁니다. 이 앱은 규칙을 먼저 고르고 그 규칙으로 답을 만들므로 인용과 답이 어긋날 구조가 없습니다.
- Microsoft HAX: "Make clear how well the system can do what it can do." → "이 상담은 근거 N개와 최근 발언 4개를 봅니다."

메모리 UX에서 반복 확인된 사용자 요구는 삭제가 아니라 **스코프**였습니다(OpenAI의 project-only memory, Claude의 프로젝트별 격리). **상담 한 건이 곧 스코프**인 구조가 그 답입니다 — 무엇을 기억할지 관리하게 하는 대신 기억의 범위를 못 박았습니다.

**Ash**는 파인튜닝 목표에 "when to stay silent"와 "appropriate opportunities to end a conversation"을 명시한 유일한 사례였습니다. 말하지 않는 것과 끝내는 것을 품질 목표로 두는 방향이 §3.6과 같습니다.

## 4. 하지 않기로 한 것

기획에서 가장 중요한 절입니다. 넣기 쉽고, 넣으면 이 앱이 아니게 됩니다.

**무한 자유 채팅.** 무엇이든 물을 수 있게 하면 근거 밖 답이 나오고, 근거 칩이 거짓이 됩니다. 축을 정하는 대가로 답이 근거에 매입니다.

**기억한다고 말하기.** 프로필을 누적하거나 "지난번에 말씀하신"이라고 하지 않습니다. 4B 모델이 실제로 기억하지 못하는 것을 기억한다고 말하면 그것은 거짓입니다. 무엇을 보는지 숫자로 적습니다.

**감정 점수·무드 트래킹.** ADR 0007의 연장입니다. 날에 등급을 매기지 않기로 한 앱이 사람의 기분에 점수를 매길 수 없습니다.

**스트릭·알림·재방문 유도.** 조사에서 확인한 것 — AI 컴패니언 앱은 작별의 37%에 감정 부하 메시지를 넣고, 그것이 참여를 14배 늘리지만 동인은 즐거움이 아니라 **분노와 호기심**입니다. 상담을 닫을 때 아무 말도 붙이지 않습니다.

**아바타·페르소나 이름.** 이름과 얼굴을 주면 관계가 생기고, 관계가 생기면 의존이 생깁니다. 모델의 말은 "명리 풀이 (AI 모델)"입니다.

**대화 제목 자동 생성.** 목록의 제목은 고민 원문의 첫 줄입니다. 제목을 위해 생성을 돌리는 것은 사용자가 주문하지 않은 일입니다.

**위기 판단을 모델에게.** OpenAI가 직접 밝혔듯 긴 대화에서는 안전 학습이 열화됩니다. 이 판단은 생성 경로 밖에 있어야 합니다.

**길흉 판정.** "이직하기 좋은 시기"라고 말하지 않습니다. 그 국면의 성격만 말합니다.

**클라우드 동기화.** 고민은 생년월일시보다 사적입니다.
